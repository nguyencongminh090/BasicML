# Session Log — 2026-07-27

## Overview
Refactoring and extending the `BasicML` custom neural network framework — decoupling layers, activations, losses, and building a composable architecture similar to PyTorch's `nn.Module`.

---

## Key Discussions

### 1. Loss Functions & Logistic Regression
- **Question:** Should `LogisticRegression` use `BinaryCrossEntropy`?
- **Answer:** Yes, conceptually. But the `forward` pass was outputting raw logits (no sigmoid), so BCE needed an explicit Sigmoid activation applied first, or a fused `BCEWithLogitsLoss`.

### 2. Decoupling Activation Functions (PyTorch-style)
- **Question:** How does PyTorch decouple activation functions like `Sigmoid`?
- **Approach:** PyTorch uses two methods:
  - **Explicit Activation:** `nn.Sigmoid()` applied separately → then `BCELoss()`
  - **Fused:** `BCEWithLogitsLoss()` (takes raw logits, combines sigmoid + BCE internally)

### 3. Architecture Design: `Activation` & `Module`
- **Decided:** `Activation` inherits from `Module`.
- **Problem:** `Module.parameters()` was `@abstractmethod`, forcing activations to implement it even though they have no learnable parameters.
- **Fix:** Removed `@abstractmethod` from `parameters()` and gave it a default `return []`.

### 4. `1/m` Placement — Gradient Responsibility
- **Bug Identified:** The `1/m` averaging factor was split wrongly — it was inside `Linear.backward()` instead of `Loss.backward()`.
- **Fix:** Moved `1/m` entirely into `Loss.backward()`. Layers now only do pure chain-rule math.

### 5. Renaming `LinearRegression` → `Linear`
- **Scope:** Workspace-wide rename.
- **Files changed:** `linear.py`, `examples/train_linear.py`, `demo/plot_dynamic_linear.py`, `examples/ref_code.py`.

### 6. `LogisticRegressionModel` — Composable Model
- **Realized:** `LogisticRegression` was identical to `Linear` after decoupling.
- **Redesign:** `LogisticRegressionModel` now composes `Linear` + `Sigmoid` internally:
  - `forward`: `logits = linear(X)` → `sigmoid(logits)`
  - `backward`: `grad_sigmoid = sigmoid.backward(grad)` → `linear.backward(grad_sigmoid)`
  - Moved to `models.py`.

### 7. `BinaryCrossEntropy` — Math Fixes
- **Bug 1:** Missing `np.sum()` — was returning an array instead of a scalar.
- **Bug 2:** `log(0)` causing `NaN` → fixed with `np.clip(y_pred, 1e-15, 1 - 1e-15)`.
- **Bug 3:** Operator precedence: `1/m * y_pred - y_true` → fixed to `1/m * (y_pred - y_true)`.

### 8. ReLU Implementation
- **Function:** `np.maximum(0, X)` for forward pass.
- **Backward:** `grad_output * (self.out > 0)` — boolean mask trick.

### 9. Weight Initialization Strategy
- **Problem:** `np.random.randn()` (unscaled) caused saturation and slow convergence.
- **Xavier / Glorot (for Sigmoid):** `scale = sqrt(1 / features)`
- **He / Kaiming (for ReLU):** `scale = sqrt(2 / features)`
- **Fix:** Added optional `init: str = 'xavier'` parameter to `Linear.__init__()`.
- **Bias** always initialized to zeros.

### 10. Training Loop & Performance
- **Problem:** `while True:` loop with `print()` on every epoch — 2M+ epochs, very slow.
- **Fix:** Print every 100,000 epochs (`if epochs % 100000 == 0`).
- **Deeper issue:** Input data `x_vals` was unnormalized (range `[0, 10]`) → slow convergence.
- **Recommendation:** Normalize with min-max or standardization.

## Final Architecture Summary

```
Module (ABC)
├── Linear(features, init='xavier'|'he')   — learnable layer
├── Activation                              — base for activations
│   ├── Sigmoid
│   └── ReLU
└── LogisticRegressionModel                 — composed model
    ├── self.linear = Linear(features)
    └── self.sigmoid = Sigmoid()

Loss (ABC)
├── MSELoss
└── BinaryCrossEntropy
```

---

## Key Takeaways
1. Each component is responsible for its own gradient — `Loss.backward()` returns `(1/m)(y_pred - y_true)`, not the raw residual.
2. Layers, activations, and models are all `Module` — composable by design.
3. Weight initialization matters: Xavier for Sigmoid, He for ReLU.
4. `print()` every epoch is a serious performance bottleneck.
5. Unnormalized inputs cause slow and unstable convergence.
