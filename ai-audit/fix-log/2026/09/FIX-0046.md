## Prompt

"Research on how to design good architecture for CNN on MNIST. Note: I have
implement Muon, you can try too." Followed, a few turns later, by
"Close 2 shells" once two background comparison runs were in flight.

## Action

- Web-searched established high-accuracy MNIST CNN design patterns
  (sources: Medium "How I Built an Efficient MNIST CNN With Under 8,000
  Parameters", GitHub `cdeotte/MNIST-CNN-99.5`) and identified the
  double-conv-per-block pattern (two 3x3 convs before each pool) as the
  main lever beyond the BatchNorm2D+GlobalAvgPool2D already used in
  TODO-0023.
- Added `BasicML/examples/train_cnn_mnist_muon.py`: double-conv-per-block
  architecture (`(Conv->BN->ReLU) x2 -> Pool -> Dropout` per stage, 3
  stages, GAP head), with parameters split into `weight_parameters()`
  (`Conv2D.w`/`Linear.w`, fed to `Muon`) and `aux_parameters()` (every bias
  + every `BatchNorm2D` gamma/beta, fed to `AdamW`) -- correcting for
  `Muon.step()`'s `ndim >= 2` check, which would otherwise also
  orthogonalize `BatchNorm2D`'s `(1, C, 1, 1)`-shaped affine parameters (not
  what Muon is designed for).
- `pyrefly check` clean. Smoke-tested both the AdamW-only baseline and the
  Muon+AdamW hybrid at `N_TRAIN=500, EPOCHS=2` -- both trained without
  error, loss fell for both, Muon showed faster early convergence in this
  tiny sample (not a claim, just a sanity check).
- The smoke test also measured real per-sample-epoch cost: ~4.7x
  `train_cnn_mnist.py`'s single-conv architecture, versus an earlier "~2x"
  guess made when scoping the experiment with the user. Reduced
  `N_TRAIN` 15000->10000 and `EPOCHS` 10->8 (keeping `N_TEST=2500` for
  comparability with TODO-0023) to bring each run to ~28 min instead of
  ~50+ min, and said so before launching rather than silently deviating.
- Launched both runs as parallel background tasks (`b5cg02fcx` AdamW,
  `bgbt8wj3v` Muon+AdamW). User then said "Close 2 shells"; confirmed this
  meant stopping these two background tasks (not terminal panes) before
  proceeding, then stopped both via `TaskStop` on explicit confirmation.

## Decision

- Building the double-conv net as a new file rather than modifying
  `train_cnn_mnist.py` in place, so TODO-0023's already-verified 96.84%
  result stays reproducible and comparable.
- Split parameters into `weight_parameters()`/`aux_parameters()` helper
  functions (rather than an inline list-comprehension per optimizer call)
  so both the AdamW-only run (`all_parameters() = weight_parameters() +
  aux_parameters()`) and the hybrid run draw from the same single source of
  truth for which tensors are which.

## Conclusion

Not fixed to a final number -- cancelled by explicit user request before
