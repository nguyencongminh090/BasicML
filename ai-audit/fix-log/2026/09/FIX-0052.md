## Decision

Found and fixed two bugs during verification, both via a standalone debug harness (not the test suite) since the test failures alone didn't localize them:
1. **`Tensor::zeros` order-of-evaluation bug**: `Tensor(std::vector<float>(numel_of(shape), 0.0f), std::move(shape), requires_grad)` — argument evaluation order is unspecified in C++, and this compiler evaluated `std::move(shape)` before `numel_of(shape)`, so `numel_of` read an already-moved-from (empty) vector, producing a size-1 data buffer that didn't match the real shape. Fixed by computing `numel_of(shape)` into a local variable before the constructor call. General lesson: never read a variable in one call argument after (or interleaved with) moving it in another argument of the same call.
2. **Gradient-check test failure was not a bug**: initial random seeds put one ReLU pre-activation at ~0.005, right at the non-differentiable kink; central-difference numerical gradients are inherently unreliable that close to a kink regardless of whether `backward()` is correct. Searched seeds for ones keeping every pre-activation `|preact| > 0.1` and used those instead, rather than loosening the tolerance (which would have masked real bugs).
