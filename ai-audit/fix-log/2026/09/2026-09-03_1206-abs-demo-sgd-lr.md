## Prompt

"@BasicML/demo/plot_dynamic_linear_abs.py I tried to set SGD optimizer but
received error"

## Diagnosis

The user had switched `optimizer = Adam(...)` to `SGD(...)` but kept
`LEARN_RATE = 0.5`. Plain `SGD.step` does `param.data -= lr * grad` on the raw
gradient, whereas Adam normalizes the step to ~`lr * sign(grad)`. On data.csv
`x` ranges to 10, so the (wrong, MSE-style) gradient from `AbsoluteLoss.backward`
is large and `lr=0.5` diverges — `RuntimeWarning: overflow encountered in matmul`
then `invalid value encountered in subtract`, final cost `nan`.

## Action

- Kept the user's `SGD` choice and their reduced `LEARN_RATE = 0.01` (verified
  stable: 400 epochs → w≈2.10, b≈-0.66, cost 0.257; converges slowly but no
  overflow). Empirically lr up to ~0.03 is safe, ~0.05+ overflows.
- Added a why-comment on `LEARN_RATE` explaining the SGD-vs-Adam scale
  difference so the overflow is not re-hit.
- `train_and_record` docstring: "full-batch Adam steps" -> "full-batch SGD
  steps".
- Left the now-unused `Adam` import in place so the user can toggle back.

## Decision

Did not raise `LEARN_RATE` or `EPOCHS` beyond what the user set — their tuning,
their teaching demo. Only explained the cause and made the docstring/comment
match reality.
