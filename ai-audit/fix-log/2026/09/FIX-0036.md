## Prompt

"Write examples" (follow-up to FIX-0035). Clarified: one scenarios script
covering the contrasting failure modes, plus a regression case using a
non-classification `error_fn`.

## Action

- New `BasicML/examples/error_ladder_scenarios.py` — five setups, each printing
  `ErrorLadder.summary(tolerance=0.035)`:
  1. underfit — `Sequential(Linear(2,1), Sigmoid())` on moons -> avoidable bias 0.11
  2. overfit — 128-wide 2-hidden MLP on 25 moons rows at noise 0.30 -> variance 0.21
  3. data mismatch — MLP, train noise 0.15, dev/test noise 0.40 -> data mismatch 0.12
  4. well-specified — MLP, all splits noise 0.15 -> ladder flat
  5. regression — `Sequential(Linear(2,1))` on `make_parabola_regression`,
     `mse_error` `error_fn`, `human_error = 0.5**2` -> ladder flat
- `basicml/diagnostics/error_ladder.py` — `ErrorLadder.diagnosis()` and
  `.summary()` gained a `tolerance` parameter (default `1e-9`, unchanged
  behaviour). A largest gap `<= tolerance` now reports
  `"ladder is flat -- every gap <= <t>"` instead of always naming a rung.
- Verified: `error_ladder_scenarios.py` and `train_error_diagnostic.py` both run
  end-to-end and produce the intended verdict per scenario; `pyrefly check`
  clean for the changed files (pre-existing `ref_code.py` errors untouched).

## Decision

- Ran the scenarios first with no tolerance: the two "flat" cases still reported
  `variance (0.015)` / `variance (0.023)` because `diagnosis()` always returned
  argmax. On finite splits there is always *some* measured gap, so a bare argmax
  is misleading for a teaching tool — added an explicit noise floor rather than
  letting the example paper over it. Default stays `1e-9` so existing callers
  (and FIX-0035's `train_error_diagnostic.py`) are unaffected.
- One combined scenarios file over one-per-gap: less `sys.path` boilerplate, and
  seeing the verdict flip across a single run is the pedagogical point.
- Regression case fits a *linear* model to a linear target, so the ladder is
  correctly flat at ~`target_noise**2`; its value is demonstrating the
  pluggable `error_fn`, not a failure mode.
