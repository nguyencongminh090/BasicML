## Prompt

"training - add display with metrics?" Clarified: a reusable PyTorch-style
per-epoch progress printer; core library only supplies the `Metric` objects, the
formatting/printing helper goes in the `basicml/visualize/` edge package; used
like `train_linear.py` -- "besides display loss, display metrics as Torch do".

## Action

- New `BasicML/basicml/visualize/progress.py` (Google-style docstrings):
  - `format_metric_line(epoch, total, values: dict[str, float], prefix="")` --
    pure formatter -> `"epoch  20/400 | loss: 0.3779 | mae: 0.7883 | ..."`,
    fixed-width epoch counter, insertion-ordered columns, `.4f`.
  - `ProgressPrinter(metrics: dict[str, Metric], every=1, loss_key="loss")` --
    `update(y_pred, y_true, loss)` accumulates a running-mean loss + feeds each
    metric; `end_epoch(epoch, total, prefix="")` prints the line (subject to
    `every`, always on the final epoch) and calls `reset()`; `values()` /
    `reset()` exposed too. Raises `TypeError` if a metric's `compute()` is not
    scalar (array-valued metrics unsupported).
- `basicml/visualize/__init__.py` re-exports `ProgressPrinter`,
  `format_metric_line`.
- `BasicML/examples/train_linear.py` retrofitted: dropped the bare
  `print(f"EPOCH ... COST ...")`, now drives a `ProgressPrinter` with
  `MeanAbsoluteError` / `RootMeanSquaredError` / `R2Score`, `every=20`; loop is
  now 1-based over `EPOCHS`.
- Verified: `python3.13 BasicML/examples/train_linear.py` prints the metric
  lines and still recovers `f(x) = 2.0000x + 0.0000`; `pyrefly check` back to the
  baseline 12 errors / 2 warnings (all pre-existing `ref_code.py` + notebook) --
  `progress.py` reports 0 diagnostics.

## Decision

- Core stays bare (CLAUDE.md): `metrics.py` already gives stateful `Metric`
  objects; display is an edge concern -> `visualize/`. No change to the core.
- `ProgressPrinter` takes a caller-supplied `dict[str, Metric]` rather than a
  fixed metric set -- keeps it problem-agnostic (regression vs classification)
  and honours interface segregation.
- Built `ProgressPrinter` on top of the pure `format_metric_line` so the
  string-building is testable / reusable without the accumulator.
- Removed a redundant `float(loss)` (pyrefly `unnecessary-type-conversion`);
  `Loss.__call__` is already typed `-> float`.
- Retrofitted only `train_linear.py` this round; `train_logistic.py` (Accuracy /
  Precision / Recall / F1) left as a follow-up.
