## Decision

- **Stateful ABC over pure functions**: matches the repo's own
  `Loss`/`Optimizer`/`Regularizer` ABC pattern and torchmetrics'
  `update`/`compute`/`reset`; state accumulation makes the metrics usable
  straight from a mini-batch loop (TODO-0011).
- **Bare core, `metrics.py` sibling to `regularization.py`**: user's call — a
  metric is a core abstraction next to loss/optimizer, not `datasets/`/
  `visualize/` edge tooling, so it carries no docstrings.
- **Shared `ConfusionMatrix`**: P/R/F1/Accuracy all read one count table
  (composition, `confusion=` injection) — high cohesion, no recomputation, and
  each metric class is reduced to its one formula.
- **Curve math in `_RankingMetric._roc`/`_pr`**: keeps `AUROC`/`AveragePrecision`
  from reaching into a sibling class's `compute` (earlier draft did
  `RocCurve.compute(self)` — pyrefly `bad-override` / `bad-argument-type`).
