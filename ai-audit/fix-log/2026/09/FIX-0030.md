## Prompt

User (Vietnamese): wants a 2-feature (x1, x2) dataset distributed in a
parabola shape, visualized the same way as the existing
`BasicML/demo/plot_dynamic_linear.py`.

## Action

- Asked clarifying questions (task type, meaning of "parabola", how to
  adapt the 5-panel visualization) since the request touched design
  decisions not derivable from the code.
- Added `make_parabola_regression()` to `BasicML/basicml/datasets/synthetic.py`
  (Google-style docstring, matching `make_moons`/`make_circles` conventions):
  samples `x1` uniformly, sets `x2 = curvature * x1**2 + noise`, and computes
  `y` as a noisy linear combination of `x1`/`x2` given true weights/bias.
  Exported it from `basicml/datasets/__init__.py`.
- Added `BasicML/demo/plot_dynamic_linear_2features.py`, mirroring
  `plot_dynamic_linear.py`'s structure (dataclass history, closed-form
  optimum via normal equation, `cost_surface`/`cost_vs_w1` grid helpers,
  `animate()` building the 5-panel figure, `FuncAnimation`). Panels 3–5 now
  sweep `(w1, w2)` instead of `(w, b)`; panel 1 became a 3D scatter of
  `(x1, x2, y)` with the fitted plane redrawn per frame (`ax_fit.plot_surface`
  removed/recreated each `update()` call, since `Poly3DCollection` has no
  `set_data`-style update method).
- Ran `pyrefly check` (only pre-existing `set_3d_properties` warnings shared
  with the other demo files, and unrelated `ref_code.py` errors — nothing
  new from this change).
- Ran the script headlessly (`MPLBACKEND=Agg`) with the project's configured
  interpreter (`/usr/bin/python3.13`) to confirm it trains and builds the
  figure without runtime errors, and rendered the initial frame to a PNG to
  visually confirm panel layout/labels. Recovered global minimum via
  `closed_form_optimum` was `(w1=2.00, w2=-0.99)`, matching the dataset's
  true weights `(2.0, -1.0)`.

## Decision

Kept the new dataset generator inside `basicml/datasets/synthetic.py`
(library-edge package, docstrings required) rather than inlining generation
in the demo script, following the existing `make_moons`/`make_circles`
pattern so it's reusable. Adapted panel 1 to a 3D fit-plane view (not
explicitly asked about) since a 2D fit-line panel has no correct
generalization to 2 input features — kept as close to the original's
"evolving fit + epoch title" spirit as possible.

## Conclusion

Fixed. New demo runs end-to-end, converges to the correct closed-form
optimum, and the 5-panel layout renders correctly (verified via headless
run + rendered PNG). TODO-0012 closed as done.
