## Prompt

Follow-up to the three trained-CNN feature-map demos (custom CNN/LeNet/
AlexNet, TODO-0020/0021/0022): "Now you can design efficient architecture
network to learn MNIST as LeNet and AlexNet is not high at 99%. Or you can
try modern Optimizer."

## Action

- Flagged before building that the ~99% numbers from the three demos are
  *train* accuracy on 1200-3000-image subsets with no held-out test set --
  not a trustworthy accuracy claim regardless of architecture/optimizer --
  and asked whether to fix that methodology alongside an
  architecture/optimizer improvement. Got explicit direction to do both,
  and to combine efficient architecture with a modern optimizer rather than
  picking just one.
- Found `AdamW` already existed in `basicml/optim/` (unused by any demo so
  far), so only the architecture side needed new library code.
- Added `BatchNorm2D` to `basicml/nn/batchnorm.py` (the pre-existing
  `BatchNorm` only accepts `(batch, features)` 2D input, not `(N, C, H, W)`
  conv feature maps) -- same derivation as `BatchNorm`, generalized to
  normalize per channel over axes `(0, 2, 3)` instead of axis `0`, `n = N*H*W`
  instead of `N`. Verified numerically against central differences:
  grad_x ~5.9e-9, grad_gamma ~3.5e-9, grad_beta ~2.1e-9.
- Added `BasicML/examples/train_cnn_mnist.py`:
  - `load_mnist_split()` -- one shuffled permutation of MNIST's 70000
    images, sliced into disjoint train (15000) and test (2500) index sets,
    so test accuracy reflects genuinely unseen digits.
  - `build_model()`/`forward()`/`backward()`/`parameters()` -- `(Conv2D ->
    BatchNorm2D -> ReLU -> MaxPool2D) x2 -> Conv2D -> BatchNorm2D -> ReLU ->
    GlobalAvgPool2D -> Linear(64,10) -> Softmax`, manual backward chain.
    `GlobalAvgPool2D` (pre-existing, unused by any demo so far) replaces the
    large flatten-into-FC pattern the LeNet/AlexNet demos use, cutting
    parameter count sharply (64->10 vs. their 256-576 -> 120-512 -> ... FC
    stacks).
  - `set_training()` -- toggles `training` so `BatchNorm2D` uses batch
    statistics while training and running statistics during evaluation.
  - `evaluate()` -- eval-mode forward-only pass reporting loss/accuracy on a
    given dataset (used for the test set only, every epoch).
  - `train()` -- `AdamW` (`weight_decay=0.01`), tracks train loss/accuracy
    from the running training batches themselves (no redundant full
    re-pass over the training set) and test loss/accuracy via `evaluate()`.
  - `plot_curves()` -- train vs. test loss and accuracy line plots.
- `pyrefly check` clean for both changed files. Smoke-tested with
  `N_TRAIN=500, N_TEST=200, EPOCHS=3` (6.2s) to confirm shapes/gradient
  flow and that train/test metrics move together, then ran the full
  configuration (`N_TRAIN=15000, N_TEST=2500, EPOCHS=10`) as a background
  task end to end (~673s / 11.2 min): loss 1.57->0.10 (train) and
  1.08->0.13 (test), accuracy 0.63->0.975 (train) and 0.76->0.9684 (test).
  Rendered and inspected the loss/accuracy curve plot from the recorded
  per-epoch logs -- train and test track closely throughout, no overfitting
  gap opening up.

## Decision

- Added `BatchNorm2D` as a second class in the existing `batchnorm.py`
  (same file as `BatchNorm`) rather than a new file -- it's the same
  derivation at a different set of reduction axes, and the existing
  `pool.py` already holds multiple related classes (`MaxPool2D`,
  `AvgPool2D`, `GlobalAvgPool2D`, `GlobalMaxPool2D`) the same way.
- Tracked train-set metrics from the running per-batch accuracy/loss during
  the training loop itself, instead of a second full forward pass over
  `X_train` after each epoch (which an earlier draft of this file did) --
  halves the redundant compute per epoch; only the test set (which the
  training loop never touches) needs its own dedicated `evaluate()` call.
- Put this in `BasicML/examples/` rather than `BasicML/demo/` and skipped
  the animated feature-map recording the three sibling scripts do -- this
  script's point is a trustworthy accuracy number and curve, not
  structural intuition, so it follows `examples/train_cnn.py`'s
  train-then-report shape instead.

## Conclusion

Fixed/working. Final held-out test accuracy: 96.84% on 2500 unseen MNIST
images (trained on a disjoint 15000), still climbing gently at epoch 10 with
train/test curves tracking closely -- a genuinely more meaningful number
than the demos' earlier ~99% *train*-on-a-tiny-subset figures, even though
it reads lower. Verification performed: gradient check on `BatchNorm2D`,
`pyrefly check`, one short smoke run, one full run (background task) with
the resulting curves inspected. No automated test suite exists in this
repo to add a permanent regression test to.
