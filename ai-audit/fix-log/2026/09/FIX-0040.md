## Decision

- Kept the model as a flat `dict[str, Module]` in the demo script instead of
  extending `nn.models.CNNModel` -- `CNNModel` hardcodes a single
  `Conv->ReLU->Pool->Flatten->Linear->Sigmoid` binary-classification shape
  and doesn't expose intermediate conv outputs; duplicating/subclassing it
  for one demo's animation needs would have been more machinery than adding
  four small script-local functions that mirror its exact manual-chaining
  pattern.
- `CrossEntropyLoss` added to the *library* (not the demo file) because
  multiclass classification is a real gap `basicml.nn.loss` didn't cover
  (only MSE/Absolute/BinaryCrossEntropy existed) and it's a direct,
  unambiguous application of this repo's documented open/closed rule ("add a
  new Loss subclass rather than branching") -- so it stayed in the bare,
  no-comment/docstring core-module style rather than being asked about.
- Left `Softmax` and `CrossEntropyLoss` as two separate modules (rather than
  a fused softmax-cross-entropy op with a hand-simplified gradient) to match
  the existing pattern where `BinaryCrossEntropy` also consumes
  already-activated probabilities and lets `backward()` drive the chain
  through the activation layer.

## Conclusion

Fixed/working. Feature maps evolve as expected -- conv1 (low-level,
already edge-detector-like even at random init on such a simple shape)
mostly sharpens slightly; conv2 (higher-level, task-specific) shows the more
visible reorganization, from diffuse to sparse localized activations, as
loss falls from 0.69 to ~0.02-0.03 and training accuracy climbs to ~99% by
epoch 15. This is the honest, correct behavior for a low-level-vs-high-level
feature evolution comparison, not a dramatic total transformation at every
layer. Verification performed: gradient check on the new loss, `pyrefly
check`, one short smoke run, one full headless run with saved frames
inspected at three epochs. No automated test suite exists in this repo to
add a permanent regression test to.
