## Prompt

Implement Muon Optimizer

## Action

- Added `BasicML/basicml/optim/muon.py`: `Muon(Optimizer)` with a per-parameter momentum buffer, optional Nesterov lookahead, and a module-level `newton_schulz5` quintic orthogonalization iteration. For `ndim >= 2` parameters the momentum-updated gradient is reshaped to 2D, orthogonalized, rescaled by `sqrt(max(1, rows/cols))`, and applied; `ndim < 2` parameters (biases) take a plain momentum step instead. File kept bare (no comments/docstrings) per the core-library convention.
- Wired `Muon` into `BasicML/examples/train_optimizer_comparison.py`'s `OPTIMIZERS` dict (`lr=0.02, momentum=0.95`) and added a bullet to the module docstring describing the family.
- Filed `ai-audit/todo/TODO-0024.md` + index row, `ai-audit/instructions/TODO-0024.md`.

## Decision

Followed the existing `Momentum`/`Adam`/`AdamW` file shape exactly (imports, `regularizer` handling, `zero_grad`) rather than introducing a new pattern. Newton-Schulz constants (`3.4445, -4.7750, 2.0315`, 5 steps) and the spectral rescale factor are the standard published Muon coefficients. Biases fall back to plain momentum rather than being excluded from the optimizer or requiring a second optimizer instance, since this repo's training loops assume one `Optimizer` per model.

## Conclusion

Fixed. Verified with `pyrefly check` (no errors attributable to `muon.py`) and by running `train_optimizer_comparison.py` end-to-end (5 epochs, `MPLBACKEND=Agg`) — Muon trains stably and reaches a comparable final BCE to the other optimizers (0.1289 vs. 0.10-0.24 range). No follow-ups.
