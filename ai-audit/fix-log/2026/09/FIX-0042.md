## Prompt

"example, use number 8" — follow-up to the two trained-CNN feature-map demos
(TODO-0020 `plot_dynamic_cnn_feature_maps.py`, TODO-0021
`plot_dynamic_lenet_feature_maps.py`), both of which previously tracked
whatever training sample happened to land at index 0 after shuffling
(digit "0" in prior test runs) instead of a chosen digit.

## Action

- Added `TARGET_DIGIT = 8` to the `CONFIG` block of both demo files.
- Added a shared-shape (duplicated, not imported -- see Decision)
  `pick_sample(X, y_int, digit)` helper to both files: finds the first
  training image whose label matches `digit`, raises `ValueError` if the
  subsampled training set has none of that digit (with a hint to raise
  `N_TRAIN` or change `TARGET_DIGIT`).
- Updated both `main()` functions to call
  `pick_sample(X, y_int, TARGET_DIGIT)` instead of hardcoding index 0.
- `pyrefly check` clean for both files. Verified with a live MNIST fetch
  (500-sample subset) that `pick_sample` actually returns a sample whose
  label is 8 in both demos.

## Decision

- Duplicated `pick_sample()` in both files rather than factoring it into a
  shared module -- these are two independent, read-top-to-bottom demo
  scripts (consistent with the "no shared helper between the two demo
  files" decision already recorded in FIX-0041), and the function is 10
  lines with no state.

## Conclusion

Fixed. Both demos now track a digit-8 sample (or whichever `TARGET_DIGIT` is
set to) instead of an arbitrary shuffled sample. Verified via a live
`pick_sample` call against a real MNIST subset in both files.
