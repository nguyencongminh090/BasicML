## Prompt

"Apply learning-rate-decay for muon" -- direct fix for TODO-0026's finding
(Muon+AdamW on LeNet diverged from ~epoch 8, ending at 73.00% test accuracy,
with a fixed `lr=0.02` reused unchanged from a much smaller MLP problem).
Followed shortly after by "stop" while the re-run was in flight.

## Action

- Added `cosine_decay_lr(base_lr, epoch, total_epochs, min_lr_ratio=0.05)`
  to `examples/train_lenet_mnist.py` and an optional `decay:
  Optional[tuple[Optimizer, float]]` parameter to `train()` that
  cosine-decays one optimizer's `lr` per epoch. Wired into `main()` as
  `decay=(muon, MUON_LR)` for the Muon+AdamW run only -- the AdamW-only
  baseline and the Muon run's auxiliary `AdamW` both keep fixed `lr`, since
  TODO-0026 isolated the divergence to Muon's own updates.
- `pyrefly check` clean (needed importing `basicml.optim.optimizer.Optimizer`
  for the `decay` parameter's type instead of a bare `object`). Verified the
  decay curve numerically (0.02 at epoch 1 -> 0.001 at epoch 15) and
  smoke-tested a short run (`N_TRAIN=1000, EPOCHS=3`) to confirm training
  still proceeds correctly with `muon.lr` being reassigned each epoch.
- Launched the full decayed-Muon re-run as a background task (`bvcn1tulq`).
  User said "stop" before it finished; stopped it via `TaskStop`.

## Decision

- Implemented the decay as a training-loop-local helper + parameter in this
  one example script, not as a new `basicml.optim` scheduler abstraction --
  this repo has no existing scheduler API (only one ad hoc `OneCycle`
  dataclass inside a single demo file, `plot_dynamic_3d_logistic.py`), and
  this is a one-off diagnostic fix for a specific observed divergence, not
  a general library feature the user asked for.
- Only decayed Muon's `lr`, leaving both `AdamW` instances fixed -- matches
  TODO-0026's diagnosis precisely rather than changing more than the
  identified cause.

## Conclusion

Code fix implemented and verified correct (type-checks, decay curve
correct, smoke-tested cleanly) but the actual outcome -- whether decay
actually prevents Muon's divergence on the full 15000-image/15-epoch run --
is unverified, since the user stopped the re-run before it produced final
numbers. `examples/train_lenet_mnist.py` is left in a state where running
it reproduces the decayed comparison on demand. No automated test suite
exists in this repo to add a permanent regression test to.
