## Description

The same 2026-09-17 review of the merged TODO-0044/0045 work also found remaining performance and memory overhead. Epoch time went from ~7.1–10 s after TODO-0044 to ~6.5–8.4 s after TODO-0045, so layout conversions were no longer the main cost; profiling has to come first. Address these findings:

1. **(P0) Profile first.** Run `perf record` + `ONEDNN_VERBOSE=1` on one epoch of `AdvanceML/examples/train_cnn_mnist.cpp` on an idle machine. Break time down by conv kernels, BN/ReLU/pool, batch gathering, optimizer, and engine/allocator overhead, and use that to order the items below. Also check the oneDNN threading settings (OpenMP/TBB, `OMP_NUM_THREADS`, affinity), since the conv kernels may now dominate.
2. **(P1) The layout registry grows forever and is searched linearly.** `intern()` (`AdvanceML/src/detail/dnnl_layout.cpp`) compares against every descriptor seen so far through the C API. It runs twice per `reorder()` and once per ReLU backward, and entries are never freed. Replace it with a hash on dims, data type, format and strides (or store layout IDs in the primitive cache entries), so cost doesn't grow with the number of distinct shapes, which matters for variable sequence lengths or batch sizes.
3. **(P2) Overhead per op.**
   - `gemm`, `pool2d`, `relu` and `batch_norm` build a `std::unordered_map<int, memory>` of execute arguments on every call, plus several `memory::desc` objects. Cut the heap allocations, e.g. cache descriptors in the primitive entries and use fixed argument sets.
   - `mse_loss`, `abs_loss`, `binary_cross_entropy` and `cross_entropy_loss` call `pred.data()`/`target.data()` inside their loops. Hoist the references out of the loops, as `softmax_cross_entropy` already does.
4. **(P3) Memory.**
   - **Duplicate conv inputs:** conv2d backward keeps both the captured `x` (needed for the saved-tensor check) and `saved_src` (the converted copy), doubling activation memory when the input layout differs from the conv's choice (first layer, or after a plain-loop op). Evaluate tracking the version without keeping `x`'s buffer alive.
   - **Heap retention:** max RSS rose 166 MB → 209 MB with default glibc malloc (148 MB with a fixed `MALLOC_MMAP_THRESHOLD_`). Evaluate a size-bucketed buffer pool for `FloatBuffer`, or `mallopt` settings, to cut both retention and allocation time.
5. **(P4) Minor.** `relu` now goes through oneDNN and only accepts 1–6D tensors (`plain_desc` throws beyond that); the old loop accepted any number of dimensions. Fall back to the scalar loop for >6D, or document the limit.
