## Description

The same code-only performance review of `AdvanceML/` (2026-09-17) that produced TODO-0044 also found overhead in the kernels and individual ops, in `AdvanceML/src/ops.cpp` and the optimizers. The review's K2 finding and TODO-0043's unfinished item 4 were folded in here as K2 when TODO-0043 closed. Address these findings:

1. **(K1) Too many layout conversions in conv2d.**
   - Cheap fixes: save the forward's blocked-layout `src_mem`/`weights_mem` in the backward closure and reuse them when the descriptors match (currently the weights are converted twice and the input twice per step).
   - Convert `diff_dst` once instead of twice (`diff_dst_opt` / `diff_dst_opt2`).
   - Cache the `dnnl::reorder` primitives in `ConvCacheEntry` instead of rebuilding them in `reorder_to`/`reorder_into` on every call.
   - Bigger fix (**design decision for the user, ask first**): let tensors stay in the blocked layout across conv → BN → ReLU → pool, using oneDNN BN/eltwise primitives or conv post-ops, to remove most conversions altogether.
2. **(K2) Scalar elementwise loops (from TODO-0043 item 4).**
   - Audit whether GCC auto-vectorizes the hand-written loops in `ops.cpp` that bypass oneDNN (`relu`, `batch_norm2d`/`batch_norm1d`, `global_avg_pool2d`/`global_max_pool2d`, `dropout`, and `exp`/`tanh`/`erf` activations such as `gelu`/`mish`/`softplus`/`swish`/`selu`/`elu`) using `-fopt-info-vec-missed`, and record per op: kept as a loop, or moved to a oneDNN primitive.
   - `batch_norm2d` forward makes 3 single-threaded passes and backward 4; `relu`, `softmax`, `dropout` and `AdamW::step` are single-threaded too, while conv uses all cores.
   - BN backward computes `grad_beta` (= `sum_dout`) and `grad_gamma` (= `sum_dout_xhat`) in separate passes (also in `batch_norm1d`); merge them, and merge the forward mean/variance passes.
   - Options: oneDNN `batch_normalization_forward/backward` + `eltwise_forward/backward` primitives, or `#pragma omp parallel for` over the channel loop.
3. **(K3) Combined softmax + cross-entropy.** Add `softmax_cross_entropy(logits, target)` with the gradient `(softmax − target) / N`: one pass, numerically stable, and no division by clipped probabilities. Use it in `train_cnn_mnist.cpp` in place of `Softmax` + `CrossEntropyLoss`.
4. **(K4) matmul.** Drop the `transpose()` copies in matmul backward by using `memory::desc::permute_axes({1, 0})` views (check with `ONEDNN_VERBOSE` that a fast non-reference kernel is still selected). Fuse `Linear`'s bias add into the matmul primitive via `DNNL_ARG_BIAS`.
5. **(K5) Allocations.**
   - Stop zero-filling output/gradient buffers that ops overwrite anyway (default-init allocator).
   - Align tensor storage to 64 bytes for AVX-512.
   - Reuse per-cache-key scratch buffers instead of allocating `dnnl::memory` on every conv call.
6. **(K6) Build flags.** Add `-fno-math-errno` (not full `-ffast-math`) in `AdvanceML/CMakeLists.txt` so loops calling `sqrt`/`exp` (AdamW, BN) can vectorize. Check with `-fopt-info-vec-missed`.
7. **(K7) Minor.**
   - Document or guard that the static `gemm_cache`/`pool_cache`/`conv_cache` aren't thread-safe and have no size limit.
   - Fix the stale comment at `examples/train_cnn_mnist.cpp:57` ("no dedicated global-pool layer yet"), and profile `GlobalAvgPool2D` against `AvgPool2D(7,7)`.

## Requirement

- Profile first: an `ONEDNN_VERBOSE=1` + `perf record` baseline for one epoch of `AdvanceML/examples/train_cnn_mnist.cpp` on an idle machine, recorded in the instructions file, so work is ordered by measured cost.
- `ctest --test-dir AdvanceML/build` still passes. New tests cover `softmax_cross_entropy` (forward value and gradient check) and matmul backward without the transpose copies.
- Before/after epoch time measured and recorded. Loss/accuracy trajectory and final test accuracy consistent with the current behavior.
- Each item (K1–K7) marked in the instructions file as done, deferred or rejected, with the reason. The K1 "keep tensors blocked end to end" option is not implemented without the user's sign-off.
