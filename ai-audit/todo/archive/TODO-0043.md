## Description

`AdvanceML/examples/train_cnn_mnist.cpp` runs very slow per epoch. Investigation during a CPU-vs-OpenCL/SYCL research session traced `AdvanceML/src/ops.cpp` and found the likely cause is not a lack of vectorization but **repeated oneDNN primitive construction**: `conv2d()` and `pool2d()` build a brand-new `dnnl::*::primitive_desc` (and JIT-select a fresh kernel) on every single forward call, and `conv2d`'s `backward_fn` builds two more (`convolution_backward_data`, `convolution_backward_weights`) on every backward call — with `kBatchSize=128` over ~60k MNIST images across `kEpochs=10`, this means thousands of primitive_desc rebuilds per epoch across 3 conv layers, dwarfing the actual (already AVX-512-VNNI-vectorized) compute. Each execute is also followed by an immediate `cpu_stream().wait()`, serializing ops that could otherwise pipeline.

Optimize AdvanceML's CPU performance:
1. Cache/reuse `dnnl::primitive`/`primitive_desc` objects across calls for a given op+shape (conv2d, pool2d, matmul in `AdvanceML/src/ops.cpp`) instead of rebuilding them every forward/backward call.
2. Reduce unnecessary `cpu_stream().wait()` synchronization points where pipelining across ops is safe.
3. Confirm AVX-512 VNNI is actually being exploited by the oneDNN kernels selected at runtime on this machine (`ADVANCEML_NATIVE_ARCH`/`-march=native` is already on by default in `AdvanceML/CMakeLists.txt`).
4. Audit the hand-written scalar elementwise ops in `ops.cpp` that do NOT go through oneDNN (`relu`, `batch_norm2d`/`batch_norm1d`, `global_avg_pool2d`/`global_max_pool2d`, `dropout`, and activations using `exp`/`tanh`/`erf` such as `gelu`/`mish`/`softplus`/`swish`/`selu`/`elu`) — determine whether compiler auto-vectorization is actually firing for these loops under the current Release + `-march=native` build, and whether any should be rewritten as oneDNN primitives (e.g. `eltwise`/`batch_normalization`) instead of raw loops.

## Requirement

- Measured, reproducible epoch-time improvement on `AdvanceML/examples/train_cnn_mnist.cpp` (report before/after wall-clock time for one epoch on real MNIST).
- No change in training correctness: loss/accuracy trajectory and final test accuracy stay consistent with the current behavior (same architecture, same hyperparameters).
- Primitive caching must remain correct across the varying last-batch size (MNIST size not evenly divisible by `kBatchSize=128`) — i.e. cache keyed on actual shape, not assumed constant.
- `ctest --test-dir AdvanceML/build` still passes after the change.
- Document (in the instructions file) which of the scalar elementwise ops were confirmed auto-vectorized vs. not, and the decision made for each (kept as scalar loop vs. moved to a oneDNN primitive).
