## Description

Direct follow-up to TODO-0026's finding: Muon+AdamW on LeNet led early
(96.80% test acc at epoch 5) but diverged to 73.00% by epoch 15 with a fixed
`MUON_LR=0.02`. User asked to apply learning-rate decay to fix it.

## Requirement

- Add a `cosine_decay_lr(base_lr, epoch, total_epochs, min_lr_ratio=0.05)`
  helper to `examples/train_lenet_mnist.py` and an optional `decay:
  Optional[tuple[Optimizer, float]]` parameter to `train()` that
  cosine-decays one optimizer's `lr` each epoch (Muon's, specifically --
  the AdamW-only baseline and the Muon run's auxiliary `AdamW` both keep a
  fixed `lr`, since the divergence was isolated to Muon's updates).
- Re-run only the Muon+AdamW variant with decay enabled (the AdamW-only
  baseline result from TODO-0026 already stands and doesn't need
  re-running) and compare against both the non-decayed Muon result and the
  AdamW baseline.

## Outcome

The code fix is implemented and correct: `cosine_decay_lr()` and `train()`'s
`decay` parameter were added to `examples/train_lenet_mnist.py` and verified
via `pyrefly check` plus a smoke test (decay curve 0.02 -> 0.001 over 15
epochs, training runs cleanly). The user stopped the background re-run
("stop") before it produced final accuracy numbers, so whether the decay
actually fixes Muon's divergence (TODO-0026: diverged to 73.00% by epoch 15
with a fixed lr) remains unverified. Cancelled rather than left in-progress
since there's no indication of an imminent resume; re-running
`python BasicML/examples/train_lenet_mnist.py` reproduces the decayed
comparison on demand.
