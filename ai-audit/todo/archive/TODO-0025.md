## Description

Follow-up to TODO-0023 (efficient CNN + AdamW, 96.84% held-out test
accuracy): user asked to research good CNN architecture design for MNIST
and try the `Muon` optimizer they had just added (TODO-0024,
`basicml/optim/muon.py`).

## Requirement

- Research (via web search) established high-accuracy MNIST CNN design
  patterns, grounded with real sources rather than asserted from memory.
- Apply the single biggest architectural lever found (double-conv-per-block:
  two 3x3 convs before each pool/downsample, popularized by Chris Deotte's
  99.5%-MNIST recipe) to a new script, kept at a comparable parameter scale
  to TODO-0023's net (16/32/64 channels) rather than published recipes'
  larger 32/64/128, to stay tractable in this repo's pure-numpy tap-loop
  `Conv2D`.
- Use `Muon` correctly: split parameters so `Muon` (Newton-Schulz
  orthogonalized momentum) only sees 2D+ hidden weight matrices
  (`Conv2D.w`/`Linear.w`), while biases and `BatchNorm2D` gamma/beta go to a
  plain `AdamW` — matching how Muon is used in practice, since blindly
  handing it everything with `ndim >= 2` would also orthogonalize
  `BatchNorm2D`'s `(1, C, 1, 1)`-shaped affine parameters, which isn't what
  the method is for.
- Train the SAME new architecture once with AdamW alone (baseline) and once
  with the Muon(weights)+AdamW(aux) hybrid, from identical initial weights,
  on the same train/test split, for a clean optimizer-only comparison.

## Outcome

Research and implementation both completed:
`BasicML/examples/train_cnn_mnist_muon.py` exists, type-checks clean, and
was smoke-tested end to end (gradients flow correctly through the deeper
double-conv architecture and the split Muon/AdamW parameter groups). The
final deliverable — a completed AdamW-vs-Muon accuracy comparison on the
double-conv architecture — was not obtained: the user stopped both
background training runs (`b5cg02fcx`, `bgbt8wj3v`) partway through via
"Close 2 shells" before either finished (~28 min runs each). Cancelled
rather than left in-progress since there is no indication the comparison
will be resumed; the script remains in the repo as a usable, correct
artifact if that changes.
