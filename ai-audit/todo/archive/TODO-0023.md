## Description

Follow-up to the three trained-CNN feature-map demos (TODO-0020/0021/0022):
user asked for a more efficient architecture and/or a modern optimizer to
push MNIST accuracy past the ~99% *train*-accuracy-on-a-tiny-subset numbers
those demos reported. Before building, flagged that the real issue is
methodology (no held-out test set, tiny training subsets) more than
architecture/optimizer, and got explicit direction to fix both.

## Requirement

- New `BatchNorm2D` in `basicml/nn/batchnorm.py` (the existing `BatchNorm`
  only accepts 2D `(batch, features)` input, not `(N, C, H, W)` conv feature
  maps) — same math as `BatchNorm`, generalized to normalize per channel
  over `(N, H, W)`. Gradient verified numerically (~1e-9 for grad_x,
  grad_gamma, grad_beta).
- New `BasicML/examples/train_cnn_mnist.py`: real MNIST train/test split (no
  overlap between the two, drawn from one shuffled permutation of all
  70000 images), an efficient architecture (`Conv2D->BatchNorm2D->ReLU->
  MaxPool2D` x2 -> `Conv2D->BatchNorm2D->ReLU->GlobalAvgPool2D->Linear->
  Softmax` — far fewer FC parameters than the LeNet/AlexNet demos'
  120-512-unit FC layers), and `AdamW` (decoupled weight decay) instead of
  plain `Adam`. Reports genuine held-out test accuracy every epoch, not
  just train accuracy.
