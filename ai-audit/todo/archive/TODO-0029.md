## Description

Follow-up critique of TODO-0028's LeNet+AdamW rewrite: (1) the conv kernel
sizes were never tunable -- hardcoded `5` in `build_model`, not even a
`LeNetConfig` field; (2) `tune_lenet_adamw.py` only did grid search, no
random-search option; (3) `tune_lenet_adamw.py`'s `main()` searched *and*
retrained the winner at full budget in one process -- the user wanted
tuning to only produce a `.cfg` file, with training as a separate run that
loads it.

## Requirement

- `lenet_config.LeNetConfig` gains `kernel1`/`kernel2` fields (both default
  5, LeNet-5's original); `train_lenet_adamw.build_model` uses them for
  `Conv2D`'s `kernel_size` and the output-size formula instead of the
  literal `5`.
- `lenet_config.py` gains `save_config`/`load_config`, round-tripping a
  `LeNetConfig` through a `.cfg` (`configparser` INI) file.
- `tune_lenet_adamw.py`: `SEARCH_SPACE` now covers `lr`, `weight_decay`,
  `kernel1`, `kernel2`. `SEARCH_MODE` selects `"grid"` (full cartesian
  product, 36 candidates for the default space) or `"random"` (default --
  `N_RANDOM_TRIALS` independently-sampled candidates, cheaper coverage of
  a 4-dimensional space than an exhaustive grid). `main()` no longer trains
  a final-validation run -- it only searches and writes the winning
  `LeNetConfig` to `OUTPUT_CONFIG_PATH` (`lenet_best.cfg`) via
  `save_config`.
- `train_lenet_adamw.py`'s `main()` gains an optional `--config PATH` CLI
  flag (`argparse`, this repo's first use of it) that loads a `.cfg` file
  via `load_config` instead of using `DEFAULT_CONFIG` -- this is how tuning
  and training now connect as two separate invocations.
