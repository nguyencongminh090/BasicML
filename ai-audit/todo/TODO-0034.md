## Description

Umbrella follow-up to [TODO-0032](archive/TODO-0032.md)/[TODO-0033](archive/TODO-0033.md) (Module/Linear/ReLU/Sequential + Loss/Optimizer base classes, done): AdvanceML now has the right *architecture* but a much thinner *component library* than BasicML. This TODO brings the component set up to rough parity with `basicml/`, still on top of the existing autograd engine — no new engine work, just new `Module`/`Loss`/`Optimizer` subclasses and supporting utilities. This is explicitly a large, multi-session umbrella: split into sub-TODOs as each area starts, rather than one PR.

Gaps to close, mirrored against their BasicML counterparts:

1. **CNN layers** (`basicml/nn/conv.py`, `pool.py`, `flatten.py`, `batchnorm.py`) — `Conv2D` (stride/padding/dilation), `MaxPool2D`/`AvgPool2D`/`GlobalAvgPool2D`, `Flatten`, `BatchNorm2D`. This is the original motivation for AdvanceML (CNN throughput on this CPU) and should land first — conv/pool forward should go through oneDNN (`dnnl::convolution_forward`/`dnnl::pooling_forward`) the same way `matmul` already goes through `dnnl::matmul`.
2. **More activations** (`basicml/nn/activation.py`) — at minimum Sigmoid, LeakyReLU, GELU, Softmax (needed for classification losses below); others (ELU, SELU, Swish, Mish, ...) as time allows.
3. **More losses** (`basicml/nn/loss.py`) — `CrossEntropyLoss` (multiclass; needs `Softmax` from #2) is the priority since it's required for any real classification example (MNIST etc.); `AbsoluteLoss`/MAE as a stretch.
4. **More optimizers** (`basicml/optim/`) — `Momentum` and `Adam`/`AdamW` at minimum (AdamW is what BasicML's CNN examples actually train with); `Muon` as a stretch, mirroring [TODO-0024](TODO-0024.md)'s BasicML implementation.
5. **Supporting utilities** — a `datasets` helper for at least one real dataset (MNIST via a C++ IDX-format loader, or CSV, to avoid depending on Python at runtime), and a minimal metrics helper (accuracy at least) so a training example can report something other than raw loss.
6. **A runnable example** — once #1-#5 give enough to build a real CNN, add an `AdvanceML/examples/` (or similar) program training a small CNN on MNIST end-to-end, analogous to `BasicML/examples/train_cnn_mnist.py` — this is the concrete proof AdvanceML delivers on its original goal (CPU CNN throughput).

## Requirement

- Each area (1-6) lands as its own sub-TODO with its own branch, tests, and fix-log entry — this TODO itself stays `open`/umbrella and is only closed once all sub-TODOs are filed and either done or explicitly deferred.
- Every new op/layer that has a non-trivial gradient gets a numerical-gradient-check test (same pattern as `AdvanceML/tests/autograd_test.cpp` and `nn_test.cpp`), not just a smoke test.
- Every new public declaration carries Doxygen docstrings per the AdvanceML code-style rules in `CLAUDE.md`, stating the math where relevant.
- `cmake --build AdvanceML/build` + `ctest --test-dir AdvanceML/build --output-on-failure` stay green throughout — no sub-TODO should land in a state that breaks previously-passing tests.
- Once the MNIST CNN example (area 6) runs, capture a rough wall-clock/throughput comparison against the equivalent BasicML example (`train_cnn_mnist.py`) in that sub-TODO's fix-log entry — this is the actual answer to "is AdvanceML worth it," not just "does it build."
