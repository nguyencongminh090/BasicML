## Description

Follow-up to [TODO-0030](archive/TODO-0030.md) (AdvanceML scaffold, done): implement the actual autograd engine — a `Tensor`/`Node` define-by-run computation graph with `backward()` — and prove it end-to-end with a tiny MLP training loop, rather than jumping straight to CNN/Transformer ops. Scalar type is float32-only for this pass; GEMM goes through oneDNN (`dnnl::matmul`) to exercise this CPU's AVX-512 VNNI.

Ops in scope: `operator+`/`operator*` (bias-add/scaling only, no general broadcasting), `matmul` (2D only), `relu`, `mse_loss`, and a minimal `SGD` step. Out of scope (future TODOs): Conv2D/pooling, general broadcasting, in-place ops, no-grad mode, other dtypes, any BasicML model port, Python bindings.

## Requirement

- `Tensor`/`TensorImpl`/`Node` implemented per the PyTorch-style shared_ptr design agreed with the user (see instructions note); `Tensor::backward()` performs a reverse topological traversal accumulating into `.grad`.
- `cmake --build AdvanceML/build` succeeds with the new sources.
- `ctest --test-dir AdvanceML/build --output-on-failure` passes, including:
  - a numerical-gradient-check test (central-difference vs. analytic `.grad` on a small graph),
  - an end-to-end 2-layer MLP training test showing real loss decrease via the new `SGD`.
- All new public declarations in `tensor.hpp`/`ops.hpp`/`optim.hpp` carry Doxygen-style docstrings stating the math (forward + backward formulas), per the AdvanceML code-style rules in `CLAUDE.md`.
