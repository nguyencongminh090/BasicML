## Description

A code-only performance review of `AdvanceML/` (2026-09-17) found overhead and missing features in the autograd engine (`AdvanceML/src/tensor.cpp`, `Node`/`TensorImpl` in `AdvanceML/include/advanceml/tensor.hpp`, and the `backward_fn` closures in `AdvanceML/src/ops.cpp`). Address these findings:

1. **(A1) Skip gradients no one needs.** Every `backward_fn` computes a gradient for all of its inputs, whether they need one or not. The worst case is `conv2d`, which runs a full `convolution_backward_data` pass for the first layer's input image, a data tensor with `requires_grad=false`. Every loss also builds `grad_target`. `Tensor::backward()` then stores gradients for data tensors such as `xb`/`yb`. Fix: when the node is created, save one "needs gradient" flag per input. Backward functions skip unneeded work, and `backward()` skips those inputs.
2. **(A2) No-grad mode.** Add a thread-local RAII `NoGradGuard` that every op checks before recording a `Node`. Evaluation (`evaluate()` in `examples/train_cnn_mnist.cpp`) currently builds the full graph, keeps saved tensors alive and fills BatchNorm's `xhat` buffer for nothing. Under the guard, use `prop_kind::forward_inference` for the oneDNN primitives where possible.
3. **(A3) Gradient accumulation and peak memory.**
   - Accumulate in place instead of through `operator+` (`tensor.cpp:148`, which allocates and runs shape checks).
   - Take over the gradient buffer on a parameter's first accumulation instead of copying it element by element.
   - Keep the gradient buffer on `zero_grad()` instead of freeing it every step, or rely on taking over the buffer.
   - Remove each intermediate gradient from `grad_of` once its node's backward has run, so peak memory isn't all gradients at once.
   - Consider releasing saved tensors after backward unless something like `retain_graph` is requested.
4. **(A4) Bookkeeping overhead per op.** Reduce the heap allocations each op makes: `TensorImpl`, `shared_ptr<Node>`, the `inputs` vector, the `std::function` state and the returned `std::vector<Tensor>`. Replace the pointer-keyed `unordered_set`/`unordered_map` in the sort with a visit counter and gradient slot on `TensorImpl`.
5. **(A5) Robustness.**
   - Make `build_topological_order` non-recursive (explicit stack) so deep graphs can't overflow the call stack.
   - Add a version counter on `TensorImpl`, checked in backward, so in-place writes through `Tensor::data()` to a saved tensor raise an error instead of producing silently wrong gradients.
   - Document that double backward (second-order gradients) isn't supported.
6. **(A6) Separate storage from tensors and stop copying.**
   - `flatten`, `identity` and `dropout` in eval mode copy the whole activation forward and backward. A reshape should share storage (`shared_ptr<Storage>` plus shape).
   - `sigmoid`, `tanh` and `softmax` copy their output twice (`out_impl->data = out_data;` then `y_copy = out_data`). Save it once without an ownership cycle through `grad_fn`.

## Requirement

- `ctest --test-dir AdvanceML/build` still passes, including the gradient-check tests. Gradients are numerically unchanged.
- Tests cover: no-grad mode records no nodes; inputs that don't need gradients get none; the version-counter error fires on an in-place change to a saved tensor; a deep chain (e.g. 100k ops) runs backward without a stack overflow.
- Before/after epoch time and peak memory (e.g. `/usr/bin/time -v` max RSS) measured on `AdvanceML/examples/train_cnn_mnist.cpp` on an idle machine and recorded in the instructions file. Loss/accuracy trajectory unchanged.
- Each item (A1–A6) marked in the instructions file as done, deferred or rejected, with the reason. A6 (storage/view split) changes a public data structure, so confirm its design with the user before implementing it.
