# TODO-0024 — Muon optimizer

## 2026-09-11

User asked to implement the Muon optimizer. Plan:

- New `BasicML/basicml/optim/muon.py`, `Muon(Optimizer)` matching the existing `Momentum`/`Adam` file shape (imports, `regularizer` handling, `zero_grad`).
- Per-parameter momentum buffer (`self.velocities`), Nesterov lookahead by default (`update = momentum * velocities[i] + grad` after updating `velocities[i]`), matching the reference Muon implementation.
- Newton-Schulz quintic iteration (`a, b, c = 3.4445, -4.7750, 2.0315`, 5 steps default) as a bare module-level function, operating on the 2D-reshaped update (conv-style `ndim > 2` params flattened to `(out, -1)` first, reshaped back after).
- Spectral scale `sqrt(max(1, rows/cols))` applied to the orthogonalized update before the `lr` step, per the Muon paper (compensates for RMS-norm mismatch between orthogonalized and raw updates at rectangular shapes).
- `ndim < 2` parameters (biases) skip orthogonalization entirely and take the plain momentum update — Muon's design intent (it's meant only for hidden-layer matrices; embeddings/heads/biases are supposed to go through a first-order optimizer instead, but since this repo has one `Optimizer` per training loop, biases fall back to the momentum term of the same optimizer rather than requiring the caller to run two optimizers).
- Wire into `BasicML/examples/train_optimizer_comparison.py`'s `OPTIMIZERS` dict.

No architecture decisions where the existing pattern didn't already dictate an answer, so implementing directly rather than asking.
