## 2026-09-02 (session: add Dropout as regularizer)

**Discussed:** User proposed Dropout "as a Module with a forward that adds a binary mask"
and asked for feedback. Confirmed the shape is right, but flagged two points:
1. Dropout is not a `regularization.Regularizer` in this repo's sense — that ABC is
   parameter-space (`penalty`/`grad` on `Tensor`, applied inside the optimizer). Dropout
   acts on activations, has no parameters → it's a plain `nn.Module` in the forward chain.
2. Dropout needs train/eval mode; `Module`/`Sequential` currently have no such concept.

Presented three options for the mode toggle:
- (a) add `train()`/`eval()` + `self.training` to `Module`, fan out in `Sequential`
- (b) local `.training` flag on `Dropout` only
- (c) `training=` kwarg threaded through `forward`

**Decision:**
- Option (a) — `train()`/`eval()` on `Module`, `Sequential` fans out to children. Default
  `training=True` so existing loops are unaffected.
- Inverted dropout: scale by `1/(1-p)` at train time, eval is passthrough.
- `backward` reuses the cached mask; passthrough path returns grad unchanged.
- **Authorship: the user writes the implementation.** AI role = design + review.
