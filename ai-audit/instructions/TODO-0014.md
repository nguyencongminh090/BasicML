**Discussed:** User asked to "write Metrics: Precision, Recall, F1, AUC, ...".
Asked to (1) read the codebase, (2) reference PyTorch architecture design,
(3) decide on architecture with coupling / cohesion in mind. Via AskUserQuestion
the user chose:
- **API shape:** stateful `Metric` ABC (`update` / `compute` / `reset`,
  `__call__` = update + compute), mirroring `Loss` and torchmetrics — not sklearn
  pure functions.
- **Placement / doc style:** `basicml/metrics.py`, **bare core** (sibling to
  `regularization.py`), no comments, no docstrings.
- **P/R/F1:** derive from a **shared `ConfusionMatrix`** (composition; injectable
  for a single shared count), not independent per-metric counting.
- **Scope:** everything — binary + threshold, ranking curves + AUC, multi-class
  averaging, regression metrics.

**Decision:** `feature/TODO-0014-metrics` off `dev`. One module `basicml/metrics.py`:
- `Metric(ABC)`: abstract `update` / `compute` / `reset`; concrete `__call__`.
- `ConfusionMatrix(Metric)`: `num_classes`, `threshold`; `matrix` (true x pred);
  probabilities → labels via argmax (2-D, C>2) or threshold (binary); one-hot
  targets accepted. `_stats()` → per-class `tp/fp/fn/support` (one-vs-rest).
- `Accuracy`, `Precision`, `Recall`, `F1Score` compose a `ConfusionMatrix`
  (constructor `confusion=` lets several share one). `average` ∈
  `binary|macro|micro|weighted|None`; safe division.
- `_RankingMetric(Metric)` pools `(score, target)`; `RocCurve`, `AUROC`,
  `PrecisionRecallCurve`, `AveragePrecision` — binary, sklearn-equivalent
  threshold sweep, trapezoidal AUC, step-sum AP.
- `_RegressionMetric(Metric)` streams `n, sse, sae, Σy, Σy²`; `MeanSquaredError`,
  `RootMeanSquaredError`, `MeanAbsoluteError`, `R2Score`.
- `RuntimeError("compute called before update")` guards throughout.
