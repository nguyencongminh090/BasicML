# TODO-0032 — AdvanceML: full Module/Layer/Loss/Optimizer API

## 2026-09-13

User flagged that AdvanceML currently has no reusable API layer — after TODO-0031 (autograd engine milestone 1), the only building blocks are free functions (`matmul`, `relu`, `mse_loss`) and one concrete `SGD` optimizer with no shared base class. Compared to BasicML's `Module`/`Loss`/`Optimizer` abstractions, this makes AdvanceML feel incomplete and hard to read/extend.

Filed as `status: open` (not `in-progress`) since the ai-audit WIP cap is currently full (TODO-0011, TODO-0024 both in-progress) — per `commit-task`'s guidance, an `open` TODO doesn't occupy a WIP slot; it only starts counting once a `feature/*` branch is actually opened for it.

Target architecture agreed conceptually with the user (mirrors BasicML's shape, not a line-for-line port):
- `Module` base (`forward`, `parameters()`) → `Linear`, `ReLU`, `Sequential`.
- `Loss` base (`operator()(pred, target) -> Tensor`) → `MSELoss` wrapping the existing `mse_loss` free function. No separate `backward()` needed on `Loss` itself (unlike BasicML) since the autograd graph already connects the loss's output tensor back to `pred` — calling `.backward()` on the result is sufficient.
- `Optimizer` base (`step()`/`zero_grad()` over `vector<Tensor>`) → refactor existing `SGD` to implement it.

Directory layout mirrors BasicML: `AdvanceML/include/advanceml/nn/` and `optim/` subdirectories, matching `basicml/nn/`/`basicml/optim/`.

Verification plan: rebuild the TODO-0031 XOR MLP test using the new `Sequential`/`Linear`/`ReLU`/`MSELoss`/`SGD` API instead of raw ops, confirming it reproduces the same loss-decrease behavior — this proves the new API is a thin, correct wrapper over the already-proven engine rather than a second, divergent implementation.

Noted in the TODO as likely spanning multiple sessions/sub-TODOs given its scope (Module+Linear+Sequential, then Loss hierarchy, then Optimizer refactor) — to be split further once implementation actually begins.
