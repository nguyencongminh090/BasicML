## 2026-09-17 17:10 (implementation)

**Discussed:** Implemented A1–A6 on `feature/TODO-0044-autograd-perf`, then measured and verified.
**Decision:** Per-item status:
- **A1: done.** `record()` stores one `needs_input_grad` flag per input when the node is created. The topological sort only follows edges that need a gradient, and every backward lambda skips unneeded work. `conv2d` skips `convolution_backward_data` when `x` needs no gradient (the first layer's data batch) and skips `backward_weights` when neither weight nor bias needs one. Losses no longer build `grad_target` for a constant target. Data tensors never get `.grad`.
- **A2: done.** Thread-local `NoGradGuard` + `is_grad_enabled()` in `tensor.hpp`. When not recording, `conv2d`/`pool2d` use `prop_kind::forward_inference` (the cache key now includes the prop kind; max pool needs no workspace), and `batch_norm2d`/`1d` and `swish` skip their backward-only buffers. `evaluate()` in `examples/train_cnn_mnist.cpp` uses the guard.
- **A3: done.** A gradient slot adopts the first incoming gradient buffer (no copy). Later gradients are added in place, but only when the buffer is uniquely owned; otherwise it is copied first, because gradients are shared (`operator+` passes the same tensor to both inputs, views share storage). A leaf's `.grad` is user-visible, so it adopts a buffer only when nothing else holds it. `zero_grad()` still resets the gradient, relying on adoption. **Chosen over** keeping the buffer, so `has_grad()` semantics don't change. Each pending gradient is moved out of its slot when its node runs, so it's freed immediately. `backward(bool retain_graph = false)` releases each node's saved state and input edges right after it runs, and drops the topological order's reference, so activations are freed during the pass. Running backward through a released graph throws.
- **A4: done, partly.** Removed the separate `std::function` allocation (a `LambdaNode<F>` template stores the lambda inside the node), the `inputs` vector (now a fixed array of `kMaxNodeInputs = 3`), the returned `std::vector<Tensor>` (now `InputGrads` = `std::array<std::optional<Tensor>, 3>`), and the pointer-keyed `unordered_set`/`unordered_map` (replaced by `TensorImpl::visit_mark` + `pending_grad`). **Deferred:** an inline shape and merging `Storage` into `TensorImpl`'s allocation. `shape()` returning `const std::vector<size_t>&` is public API, and the remaining allocations weren't measured as a bottleneck.
- **A5: done.** The topological sort is now iterative (explicit stack). `Node::~Node` also tears down exclusively-owned upstream nodes from a worklist, because destroying a deep graph without running backward would otherwise recurse once per level. Version counter on `Storage`, bumped by `Tensor::mutable_data()` (user-confirmed API; `data()` is now const-only). Each node records the versions of the storages it saved and checks them before its backward runs. Double backward is documented as unsupported (backward runs under `NoGradGuard`) in `tensor.hpp` and the README.
- **A6: done** (user-confirmed design). `Storage{std::vector<float> data; uint64_t version;}` behind `shared_ptr` in `TensorImpl`. `flatten`, `identity` and inference/`p == 0` `dropout` return whole-buffer views via `detail::view()`, with no copy forward or backward. `sigmoid`, `tanh` and `softmax` save their output by capturing `out`'s storage `shared_ptr` (no `TensorImpl`, so no cycle through `grad_fn`) instead of copying it twice.
- Breaking API: optimizers take one `mutable_data()` reference per parameter per step. Test helpers write through `mutable_data()`.

**Verification:**
- `ctest --test-dir AdvanceML/build`: 68/68 (59 existing, including gradient checks, + 9 new in `tests/autograd_engine_test.cpp`: no-grad records no nodes, inference conv/pool forward matches the recorded forward, unneeded inputs get no gradient, conv2d parameter gradients identical with and without `x.requires_grad`, version-counter errors (saved input, saved output, write through a view, reads don't count), 100k-op chain for backward, retained-graph teardown and never-backpropagated teardown, `retain_graph`, accumulation without aliasing, views share storage).
- The whole suite also passes under `-fsanitize=address,undefined` with leak detection (2817 assertions, no reports).
- **Benchmark** (`/usr/bin/time -v`, full 10-epoch `train_cnn_mnist`, baseline = `dev` `64782ae`). **Caveat: the machine was not idle** (load average 5.7–9.2 from other sessions), so wall times are noisy:
  - Baseline: 332.58 s total. The first 4 epochs took 55–62 s under a load spike; epochs 5–10 took 14–18 s. A rerun on a quieter machine gave 14.3/18.2/16.0/16.1 s. Max RSS 242,724 KB.
  - New: 80.74 s total, epochs 7.1–10.0 s (rerun 7.0–8.4 s). Max RSS 163,416 KB (**−33%**).
  - Comparing the quieter baseline epochs (~14–18 s) with new (~7–8 s): about **2x per epoch**. A clean idle-machine re-measurement would tighten this number.
- **Loss/accuracy trajectory.** Both binaries are deterministic run to run, but the default `-march=native` build drifts in the 4th decimal from epoch 2 onward (for example, epoch 10 test_acc 0.9632 → 0.9644). Bisected: not `NoGradGuard`, not the AdamW loop hoist, not the conv `backward_data` skip. The cause is FMA contraction: GCC's default `-ffp-contract=fast` under `gnu++23` fuses `a*b + c` differently once loops are rewritten, for example with `x.data()` hoisted into local references. Proof: rebuilding **both** baseline and new with `-ffp-contract=off` gives identical train loss/accuracy to 8 decimals over 2 epochs (1.35406637/0.67820001, 0.50849485/0.92479998). The only difference is test_loss at 3e-8, from the inference-mode conv kernel. Gradients are numerically unchanged.
