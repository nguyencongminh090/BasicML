## 2026-09-17 18:05 (implementation + verification)

**Discussed:** Implemented K1–K7 on `feature/TODO-0045-op-kernel-perf`, following the order from the profile.
**Decision:** Per-item status:
- **K1: done, including the user-approved "keep tensors blocked end to end".**
  - Design: `Storage` gained `std::shared_ptr<const detail::Layout> layout`, where null means plain row-major. `detail::Layout` wraps an **interned** `dnnl::memory::desc`, so its address is a cheap cache key. It lives in the private header `src/detail/dnnl_layout.hpp`, so public headers don't pull in `dnnl.hpp`. `conv2d`, `batch_norm2d`/`1d`, `relu`, `max_pool2d`/`avg_pool2d` and the global pools return tensors in whatever layout oneDNN picked. The next op uses them directly when the layout matches its primitive.
  - `Tensor::data()`/`mutable_data()` convert a blocked storage to plain **in place** on first read (`materialize_plain`). The logical values don't change, so the version isn't bumped. A view whose shape doesn't match the layout's dims (e.g. `flatten` of a blocked `(N,64,1,1)`) is converted first. Gradient accumulation adds raw buffers when both layouts match and converts to plain otherwise. Leaf `.grad` is always plain. `Tensor::numel()` now comes from the shape, because blocked buffers can carry channel padding.
  - Safety: backward functions never keep a `dnnl::memory` that only *views* a tensor's storage, because a later `data()` read would free that buffer. They keep oneDNN-owned conversions (conv's converted src/weights) and otherwise look the storage up again at backward time.
  - Cheap fixes: the forward's converted src/weights are reused in backward (converted again only if the backward primitive picked a different layout); `diff_dst` is converted once and shared by `backward_data` and `backward_weights`; reorder primitives are cached per layout pair (`detail::reorder`).
  - ReLU uses `eltwise_relu_use_dst_for_bwd` and saves its **output** instead of its input. The version-counter test for "a saved input" switched from `relu` to `leaky_relu`, and a new section checks relu's saved output.
  - Conv post-ops were not used, because BN sits between conv and ReLU in this model.
- **K2: done.** Per-op outcome:
  - Moved to oneDNN primitives, now multi-threaded and blocked-layout: `relu` (eltwise); `batch_norm2d` and `batch_norm1d` (one shared `batch_norm` over an `(N,C,1,1)` view; forward and backward are single oneDNN calls, so the separate mean/var and grad_beta/grad_gamma passes are gone); `global_avg_pool2d`/`global_max_pool2d` (oneDNN pooling with an H×W kernel).
  - Kept as loops: `dropout` (per-element `mt19937` draw, inherently serial, not in the example); the `exp`/`erf`/`tanh`/`log1p` activations `gelu`, `elu`, `selu`, `softplus`, `mish` (`-fopt-info-vec` shows these don't vectorize, and they're not in the hot path); `swish`, `sigmoid`, `tanh`, `leaky_relu`, `hardtanh`, `hardsigmoid`, `softmax` (at least one loop each reported as vectorized by `-fopt-info-vec-optimized` with K6's flag; not checked without it); `AdamW::step` (vectorized only because of K6, checked both ways; parameters are about 25k floats, so threads wouldn't pay off).
  - No OpenMP pragmas were added: nothing serial is left in the example's hot path (the new perf profile shows no AdvanceML scalar symbols on the main thread).
- **K3: done.**
  - New op `softmax_cross_entropy(logits, target)`: log-sum-exp with max subtraction, no clipping. Gradient `(p·sum(t) − t)/N`, which is `(p − t)/N` for normalized targets, plus a target gradient `−log_softmax/N`.
  - New `SoftmaxCrossEntropyLoss` class. `train_cnn_mnist` drops its `Softmax` layer and uses the fused loss; accuracy uses argmax over logits, which is unchanged.
- **K4: done.**
  - matmul backward passes `memory::desc::permute_axes({1,0})` views instead of `transpose()` copies. `ONEDNN_VERBOSE` shows every call still uses `gemm:jit:f32`.
  - New op `linear(x, w, b)` fuses the bias through `DNNL_ARG_BIAS` and records one node. `Linear::forward` uses it.
- **K5: done.**
  - `advanceml::FloatBuffer = std::vector<float, AlignedDefaultInitAllocator<float>>`: 64-byte `operator new(align_val_t)`, and elements are default-initialized, so `FloatBuffer(n)` is not zero-filled. This is a breaking change for explicit `std::vector<float>&` bindings: optimizers, accuracy, mnist, the example and 2 tests were updated. A constrained template constructor still accepts `std::vector<float>` (copied) without making braced-list construction ambiguous.
  - Per-cache-key scratch: conv's blocked `diff_weights` buffer is kept in `ConvCacheEntry` and reused every step. Forward outputs can't be reused, since they become tensor storage.
- **K6: done.** `-fno-math-errno` is PRIVATE on the `advanceml` target. Verified: `AdamW::step`'s loop reports "not vectorized: unsupported control flow" with `-fmath-errno`, and "loop vectorized using 32 byte vectors" without it.
- **K7: done.**
  - A comment on the static caches (ops.cpp, dnnl_layout.cpp) plus `Tensor`'s class docs state that the caches are unbounded and not thread-safe.
  - Fixed the stale "no dedicated global-pool layer yet" comment; the example now uses `GlobalAvgPool2D`.
  - Profiling `GlobalAvgPool2D` against `AvgPool2D(7,7)`: both now run the same oneDNN `pooling_avg_exclude_padding` primitive on a 7×7 input (kernel 7, stride 1 vs 7, giving the same 1×1 output), so they cost the same by construction. Before this change `global_avg_pool2d` was a scalar loop that also forced a conversion to NCHW.
