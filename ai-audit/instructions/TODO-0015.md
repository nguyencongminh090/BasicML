**Discussed:** User: "Add represent text for Layer code. (`__repr__`, `__str__`,
and other magic methods)". Read the `nn/` package via codegraph — `BatchNorm`,
`Dropout`, `Sequential` already carried a hand-written `__repr__`; `Module`,
`Linear` and every activation class did not (they fell back to the default
object repr).

**Decision:** No new user-facing API decision needed — additive, follows the
`__repr__` precedent already in the repo.
- `Module.__repr__` → generic `f"{type(self).__name__}()"`; this alone covers
  the zero-config activations (`ReLU`, `Sigmoid`, `Tanh`, `Identity`, `SELU`,
  `Softplus`, `GELU`, `Mish`, `Hardsigmoid`) and `Activation`.
- `Linear.__repr__` → `in_features`, `out_features`, `bias`, `init_type`.
- Override `__repr__` on the parametrized activations only: `LeakyReLU`
  (`negative_slope`), `PReLU` (`num_parameters`), `ELU` (`alpha`), `Swish`
  (`beta`), `Hardtanh` (`min_val`, `max_val`), `Softmax` (`axis`).
- `Sequential` — kept its multi-line child-listing `__repr__`; added `__len__`,
  `__getitem__`, `__iter__` over `self.layers` (the "other magic methods").
- `__str__` intentionally not defined — Python falls back to `__repr__`, which
  is what we want.
- Style: no comments / docstrings / return annotations on the dunders, matching
  the existing `__repr__` in `dropout.py` and `sequential.py`.
